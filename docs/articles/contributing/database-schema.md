# Database schema

The Server's Postgres schema is owned by [dbdeploy](https://github.com/gigi81/dbdeploy) scripts under
`db/`, **not** by EF Core migrations. There is no `Migrations` folder and no `dotnet ef database update`.

```text
db/
  dbsettings.json   provider and connection string per database ("server" → etlpipelines_server)
  main.csv          the ordered list of scripts dbdeploy deploys
  server/
    _Init.sql       the baseline schema
```

## Tables

| Table | Holds |
|---|---|
| `Packages` | One row per NuGet package id ever installed. |
| `PackageVersions` | One row per installed version: `Installing`, `Installed` or `Failed`. The pair (package, version) is unique. |
| `Pipelines` | One row per pipeline name within a package version, as reported by the package's `list` verb. |
| `Agents` | Every agent registration: machine name, tags, version, `Online`/`Offline`, `LastHeartbeatAt`. |
| `Runs` | One row per execution. `Id` is the session id the pipeline process is given. Holds status, timestamps, exit code and row counts. |
| `StageResults` | One row per completed stage of a run. |
| `AgentResourceSamples` | CPU and working-set samples per run. Nothing writes to it yet. |
| `ConfigurationEntries` | Flat `IConfiguration` keys with Data Protection-encrypted values. |
| `NuGetFeeds` | Exactly one row: the feed from `NuGetFeed:Url`, rewritten on every Server start. |

Every `Id` is a GUID the application creates, so no key is generated by the database.

## Changing the schema

1. Add a `.Deploy.sql` and a matching `.Rollback.sql` under `db/server/`, and append the change to
   `db/main.csv`. Never edit a script that has already shipped. Deployed databases have already run
   it.
2. Check it against a local Postgres (`db/dbsettings.json` points at `127.0.0.1:5432`):
   ```bash
   docker run -d --name etl-db -p 5432:5432 -e POSTGRES_PASSWORD=postgres \
     -e POSTGRES_DB=etlpipelines_server postgres:15.1
   dbdeploy validate --path db
   dbdeploy deploy --path db
   dbdeploy ci --path db        # deploys, rolls everything back, deploys again
   ```
3. Regenerate the EF Core model. `ServerDbContext.cs` and `Entities/*.cs` in
   `src/EtlPipelines.Server.Database` are produced by `dotnet ef dbcontext scaffold` against the
   deployed database. Never edit them by hand. The exact command is in that project's `README.md`.
   Anything scaffolding cannot express goes in `ServerDbContext.Customizations.cs`.
4. `db.yml` runs step 2 in CI. The `Server.Database` step of `ci.yml`'s Databases job deploys the
   scripts into an empty Testcontainers Postgres and reads and writes through the scaffolded model,
   which proves the two agree.

In Docker Compose, the Server's entrypoint runs `dbdeploy deploy` on every start, so a new script
reaches a running stack the next time the `server` image is rebuilt and restarted.
